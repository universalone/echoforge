# EchoForge

**Next-gen emulation, reforged.** A launcher for PS5, Xbox One, PS4, PS3, Xbox 360, Xbox, Wii, PS2, GameCube, PS1 and PSP, with one library across every drive.

> **Early preview (v0.1).** Expect rough edges. It has mostly been used on one PC, and the installer isn't code-signed yet. PS5 and Xbox One support is experimental: those emulators boot only a few titles and most games won't play.

## Run it
```bash
npm install
npm start
```

## Build the installer
```bash
npm run dist
```
This writes `dist\EchoForge-Setup-<version>.exe`, an assisted installer: you choose the folder (default `%LOCALAPPDATA%\Programs\EchoForge`), and it adds Desktop and Start menu shortcuts. Settings and library live in `%APPDATA%\EchoForge`, so they carry over between the dev build and the installed app. The installer isn't code-signed yet, so Windows SmartScreen will warn the first time you run it.

## What's in it
- **Splash screen**: animated forge logo, ember particles and real loading progress.
- **Console sections** grouped Next-Gen / Current-Gen / HD Era / Classics. Each section has its own library, setup and "Tuned for your PC" tab.
- **Libraries on any drive**: several folders per console, labelled NVMe / SSD / USB HDD. Games on an unplugged drive show as offline instead of being deleted. Standard layout: `<ROM root>\<Console>` (Playstation, Playstation 2–5, Xbox, Xbox 360, Xbox One, GameCube, Wii, PSP). Change the root in Settings → Library, and **Create & add folders** sets up every console at once.
- **Game storage tiers**: whether a game needs an SSD depends on its console, never its size. PS4, PS5 and Xbox One games belong on the fast library (SSD/NVMe). PS3, Xbox 360 and older games belong on an optional storage library (a hard drive is faster than their original discs). Each game page says "Needs an SSD" or "No SSD needed". Your PC → Game storage lists the games on an SSD that don't need one, biggest first, with Show file and Move buttons, plus games on the wrong drive, which move with one click or all at once: copy, verify byte counts, then delete the original. Playtime, favorites and covers carry over.
- **Box art**: games without their own icon get a cover from the libretro thumbnails library (the one RetroArch uses), matched by No-Intro/Redump name with a USA-first fallback. PSP games without box art show the disc's own ICON0.PNG over its PIC1.PNG menu background, which is also used as the full-screen backdrop. PS3 games can use box art from GameTDB by disc title ID (the free libretro library has only a few dozen PS3 covers), off until you turn it on in Settings → Library. Xbox 360 games can fall back to XboxUnity, off until you turn it on: EchoForge reads the title ID from the disc's `default.xex` and crops the front out of full wraparound scans. Covers are cached in `%APPDATA%\EchoForge\covers`, and Settings → Library can turn this off.
- **Import folder** (`app/inbox.js`): checks the folder you choose and reads each archive's or disc image's own data to tell PS1, PS2, PS3, PSP, Xbox, Xbox 360, GameCube and Wii discs and PS3/PS4 packages apart. Supported formats: .7z/.zip/.rar, ISO, CSO, CISO, RVZ and WBFS. **Add all** unpacks each game to its console's library on the right drive tier (or the other drive when space is short), checks every file's size, adds it with artwork and sends the archive to the Recycle Bin. PS3 discs become RPCS3 game folders, and encrypted dumps are refused. PS3 games packed as a folder (`PS3_GAME`) are unpacked as "Title [ID]" from their PARAM.SFO. The list shows every file at once and each one moves to Ready as soon as it's checked (a fraction of a second for most archives: 7-Zip runs single-threaded for these small reads, which starts streaming immediately, and one stream covers every spot a check needs). What's known about each file is kept in `inbox-cache.json`, so a restart doesn't check everything again. Password-protected archives are reported as such right away (7-Zip is never left waiting for a password), and any file that can't be read within a minute is set aside so it can't hold up the rest. Full original Xbox disc images (with the video section in front) are recognised, and only the game part, a normal XISO, is kept. PS3 packages are installed through RPCS3, with a warning when the game needs a license file. RPCS3 stays open after an install, so EchoForge watches its log for that package's result and closes it (with a time limit of an hour plus a minute per GB). **Cancel**, next to the progress bar, stops the import that's running and the rest of Add all: 7-Zip or RPCS3 is ended, anything half-unpacked is removed, and the archive is kept. DVD-video bonus discs are recognised as not games. Installers and shortcuts in the folder are never run. Needs 7-Zip.
- **Downloads drive** (`app/downloads.js`, off until you turn it on in Settings → Import): when the drive holding Windows' Downloads folder drops below 100 GB free (adjustable), EchoForge points Downloads at `D:\Downloads` (adjustable). It's the same per-user setting as Downloads → Properties → Location, so Edge, Chrome and other apps save new downloads straight to that drive after a restart. Files already downloaded aren't moved, and it won't switch to a drive that's low too or unplugged. While it's on, games you import follow the same limit: if their usual drive would drop below it, they go to the other library drive. Settings → Import can switch it back or turn it off. Free space is checked at start and every 10 minutes.
- **Shared games** (`app/share.js`): for moving your own games between your own PCs. Turn on sharing on one PC, then on another PC enter its name or address and the code, tick the games you want and press Install. Only those games are copied, each file is checksum-checked, and a stopped install picks up where it left off. Sharing is off by default, read-only, answers only private network addresses and runs only while EchoForge is open. Traffic isn't encrypted. Emulators can be copied the same way into `%LOCALAPPDATA%\Programs` and are linked automatically; saves, caches, firmware and games inside an emulator's folder stay behind, and nothing already on the other PC is replaced.
- **Splash screens**: Settings → Appearance → Splash screen. Seven original styles (EchoForge, Cartridge, Disc, Orb, Cube, Neon, Minimal), inspired by console eras but with no console makers' logos, or your own picture or video (PNG, JPEG, WebP, GIF, MP4, WebM up to 300 MB; EchoForge keeps a copy in `%APPDATA%\EchoForge\splash`). Every style shows EchoForge's name and the real loading progress. Card, large or full-screen size, a minimum time on screen, and videos can play to their end (up to 15 s) with or without sound. Preview plays it without restarting.
- **Library safety**: the library file (`echoforge-data.json`) is written through a temporary file, and a copy is kept for each of the last 7 days in `library-backups`. If the file is ever damaged, it's set aside as `.damaged-…` and the newest good copy is loaded, with a message saying so. A save that fails (full disk, locked file) shows a warning.
- **Window safety**: the main window runs sandboxed like the splash and in-game menu, never navigates away from EchoForge (dropped files are ignored, web links open in your browser), and "Open folder" only opens folders.
- **Synopses** (`app/synopsis.js`): each game page shows the first paragraph or two of the game's Wikipedia article, with year, genre, developer and publisher from Wikidata and a From Wikipedia link (the text is CC BY-SA). Only the game's name is sent. Articles must be described as a game and their name must match, so a short name never gets a different game's article, and a sequel never stands in for the first game. When an original and its remake share a name, the article that mentions the console wins, then the oldest. Results are saved with the library; misses are retried after 30 days. Manage → Synopsis takes your own text, looks the game up again, or marks a match as the wrong game. Settings → Library can turn this off.
- **"Will it run?" badges** (`app/compat.js`): PS3 games are looked up on RPCS3's compatibility list and Xbox 360 games on Xenia Canary's tester tracker, by disc title ID only. Each cover shows Playable / Runs with issues / Won't play yet / Not tested yet, and the game details show the test date, a link to the tester report and known tweaks. EchoForge asks once before launching a game that's reported not to work. Results are cached for a week (`compat-cache.json`), and the lookups can be turned off in Settings → Library.
- **Collections**: series are found from titles across every console (Star Wars, SOCOM, Spider-Man, Tony Hawk's and so on). Games that share their opening words are grouped. A generic one-word start like "Dead" needs a second shared word, and "Escape Dead Island" still joins Dead Island. They appear on a Collections page, a Home shelf and as a library filter. In a game's details, type a collection name to move it, or "-" to keep it out of collections.
- **Save backups** (`app/backup.js`): finds each emulator's save folders (portable or Documents installs) and copies them into dated snapshots under `<backup folder>\<emulator>\`:
  - **Sources**: RPCS3 saves, trophies and licenses; PCSX2 and DuckStation memory cards and states; PPSSPP SAVEDATA; Dolphin GC, Wii and states; only the Xenia save folders (not DLC or updates); xemu's HDD image and EEPROM; shadPS4 and RetroArch saves.
  - **When**: after every game session and weekly. A backup is skipped when nothing changed.
  - **Retention**: keeps the newest 10 per emulator (adjustable), and older snapshots go to the Recycle Bin.
  - **Restore**: refuses while the emulator is running and backs up the current saves first.
  - **Location**: defaults to `<storage drive>\EchoForge Backups`.
- **Game page**: clicking a game opens a full-screen page.
  - **Backdrop**: the game's own art, in this order: the PS3/PS4/PSP `PIC1.PNG` background read from the disc, an in-game screenshot or title screen from libretro's `Named_Snaps` / `Named_Titles`, or a blurred cover.
  - **Layout**: a large title, the "will it run?" result, its collection, a screenshot strip and "More in <collection>".
  - **Manage**: rename, cover, collection, emulator, launch options, file, hide, remove and send to the Recycle Bin. The bin button shows the files and size first, keeps saves, refuses a folder that also holds another game, and refuses any game too big for that drive's bin, because Windows would delete it for good.
  - **Titles**: shown like the box ("Simpsons Game, The" becomes "The Simpsons Game", "Star Wars - Battlefront II" becomes "Star Wars: Battlefront II").
  - **Cards**: tilt toward the pointer and catch a sweep of light (full motion only).
- **Smart scanning**: reads PS4/PS5/PS3 `PARAM.SFO` / `param.json` for real titles and IDs and uses each game's own icon as cover art. Cleans No-Intro/Redump names.
- **Foolproof launching**: every console shows Emulator / Firmware / Games checks. Play is never a dead end: a "needs a quick fix" dialog sends you straight to the fix. Also: low-RAM warning, and a plain-English message when an emulator closes right away.
- **Firmware & BIOS checker**: per-console folders, MD5 verification (e.g. Xbox MCPX), "installed in emulator" ticks, links to official sources. EchoForge never downloads or copies firmware.
- **Home dashboards**: Settings → Home dashboard switches between ready-made dashboards (Classic, Couch with big covers for the TV, Collector with a shelf per console, Minimal, Discover) and lets you turn sections on or off, reorder them, choose the cover size, pair a skin, and save your own, with a Preview tab that shows Home before you switch. Every customizer (skins too) lives in Settings. Pin to Home on a game's page adds it to the Pinned shelf.
- **Skins** (`app/skins.js`): Settings → Appearance → Skin. Nine built-in skins; skins made from any game's cover (colors picked from the art, the art as wallpaper); generated skins; and a customizer for every color (accents, background, panels, text, borders), heading and body fonts (24 Windows fonts or any installed font), corner style and size, border style and thickness, and panel see-through. **Colors follow the selected game** changes the accent live. Skins are shared as `.efskin` files: JSON with colors and an optional JPEG/PNG/WebP picture, validated on import, never code.
- **Racing wheels** (`app/wheels.js`): Settings → Controller → Racing wheel learns the wheel's steering axis, pedals and buttons by asking you to move them. A game's page then has Use racing wheel (PS3 and PS2): before it starts, EchoForge sets RPCS3's Logitech G27 emulation (`config/LogitechG27.yml`, aimed at the wheel by vendor and product id) or PCSX2's Driving Force on USB port 1 (`[USB1]` in `PCSX2.ini`), and switches them off for other games. The first time a file is changed the original is kept as `*.before-echoforge`. RPCS3's G27 reads a released pedal at the top of the axis, like Logitech's own pedals, so pedals that rest at the bottom (Moza, Fanatec, Thrustmaster) are set to `reverse`. Xbox 360 games get the wheel as an Xbox controller (an SDL mapping handed to Xenia); Use racing wheel is on by default for Xbox 360 games whose PS3 or PS2 version is on the wheel list, like DiRT 3. PS4, PS5 and Xbox One emulators don't support wheels yet. **Wheel profiles**: one saved layout per wheel or rim (rims on the same base put buttons in different places). Settings → Controller → Racing wheel lists them; + New profile learns another, and the selected one is what games use. A wheel game's page has a Rim button that switches to the next profile. A wheel set up before profiles existed becomes the first one.
- **Pictures and memory**: covers, icons and backgrounds reach the window as `efimg://` addresses (served by `main.js`, picture files only), not as base64 text the page kept forever. Cards and thumbnails get a 480-pixel copy, made once and kept in `thumbs` in EchoForge's data folder. After a page change Chromium is told to let go of pictures no longer on screen. Browsing every page used to grow the window past 2 GB and keep it there; it now stays around 300–550 MB.
- **Retro Forge** (the button right of the search bar): starts EchoForge Retro Gaming without its own window (`--no-window`) and shows its page (127.0.0.1:8765) in place of the main area. It stays loaded while EchoForge is open, so going back to it is instant. While it's showing, the controller belongs to Retro; Start comes back to EchoForge. Retro shuts itself down 90 seconds after EchoForge closes.
- **Controller highlight**: what the controller is on gets a thick glowing ring (`.gp-focus`), which comes back after the page is redrawn and goes away when the mouse moves. The browser's own focus ring only shows after keyboard use, so it can't be relied on.
- **In-game menu** (`app/pausemenu.js`, `app/overlay.html`): a quick tap of Select + Start (Share/Create + Options, Back + Start) or Ctrl+Shift+P opens a see-through menu on the game's screen: Resume, Quick save / Quick load (RetroArch, PCSX2, PPSSPP and Dolphin, by their default keys), Take a screenshot (saved to Pictures › EchoForge Screenshots, taken just before the menu appears), Controller check and Quit to EchoForge. The game's process is paused while the menu is open (Settings can turn that off). PS and Guide aren't used because RPCS3 and the Xbox Game Bar already open their own menus on them.
- **Quit to EchoForge** (`app/quit.js`, `app/padwatch.ps1`): while a game runs, holding Select + Start for 2 seconds (Share/Create + Options, Back + Start) or pressing the quit shortcut (default Ctrl+Shift+Q) closes the game. EchoForge first asks the emulator to close the way its window's X button does, so it can save, and only forces it after 10 seconds. The controller watcher reads XInput and PlayStation HID reports with shared access, never sends input, and runs only while a game is open.
- **PS3 controller setup** (`app/pads.js`): a fresh RPCS3 has no controller profile, so games fall back to the keyboard. EchoForge recognises a connected PS4, PS5 or XInput controller and writes a standard profile to RPCS3's `config/input_configs/global/Default.yml` before a PS3 game starts, and the PS3 page shows a **Set up controller** button. A profile made in RPCS3 is never replaced without asking, and a replaced one is kept as a backup.
- **PS2 setup** (`app/pads.js`): a PCSX2 that has never been opened waits on its first-time setup window and ignores the game it's given, and its PS2 controller is on the keyboard. Before a PS2 game EchoForge finishes that setup (choosing a BIOS from PCSX2's BIOS folder when none is chosen, and adding `SettingsVersion`, without which PCSX2 resets the file) and, when player 1 has keyboard keys only, maps the controller in any of the first four controller slots (a wheel often takes the first; wheel inputs have other names, so it can't press PS2 buttons). Keyboard keys stay, a mapping you made is never changed, and the original file is kept as `PCSX2.ini.before-echoforge`.
- **EchoForge updates** (`app/app-updates.js`): once a day (Settings → General can turn this off) EchoForge checks the GitHub Releases of the repository named in `package.json` (`updateRepo`) for a newer `EchoForge-Setup-x.y.z.exe` with a SHA-256 published by GitHub. Home and Settings → About offer **Update now**: EchoForge downloads the installer, checks it, then closes and opens it. Library and settings are kept. Drafts and pre-releases are skipped.
- **Emulator updates** (`app/emu-updates.js`): KytyPS5 and shadPS4 are checked once a day against their official GitHub releases (Settings → General can turn this off). Only Windows builds with a SHA-256 published by GitHub are used. Each emulator has a choice on the Emulators page: **Tested** (the default: shadPS4's stable releases, or KytyPS5 builds out for at least two days), **Latest** (every build, including shadPS4's daily pre-releases) or **Keep this version** (no updates). Switching to Tested never downgrades. **Update** downloads the build, checks the checksum, backs up the files it replaces and copies the new ones over, so settings and saves in the emulator's folder stay. **Roll back** puts the previous version back; the 2 newest backups are kept in `%LOCALAPPDATA%\EchoForge\emulator-backups`. Nothing updates while that emulator is running, and nothing installs until you press Update. Needs 7-Zip.
- **Xbox One** (`app/appx.js`): WinDurango has no emulator program, so Xbox One needs nothing linked. Once a game is installed with WinDurango's steps (its files copied into the game, Windows Developer Mode on, `Add-AppxPackage -Register .\AppxManifest.xml`), Play reads the game's AppxManifest.xml, finds the registered package and starts it, then watches the game's process for play time and the exit. EchoForge never registers packages, copies files or changes Windows settings itself.
- **Guide and tour** (`app/guide.js`): a step-by-step manual on the Guide page (left menu or F1), with search and Take me there buttons that open the right page. A short tour of the screen runs once after setup on a first install, never after updates, and any time from the Guide or the New here? card on Home.
- **Hardware-aware**: detects GPU/VRAM, CPU threads, RAM and drive types, and recommends emulator settings for this machine. Game mode minimizes the launcher, pauses its effects and raises emulator priority.
- **Controller navigation** (A/B/X/Y, LB/RB sections), **Big Picture** (F10) and full keyboard support.
- **Settings**: general, appearance (6 accents, dark/OLED/light, neon effects: breathe, pulse, chase, flicker, color cycle or steady, with adjustable speed, the highlighted game as a blurred full-screen background, cover size and shape, UI scale), library, launching & performance, controller, sound, Big Picture, accessibility, backup/restore.

## Layout
```
app/main.js        Electron main: windows, storage, scanning, SFO parsing, firmware checks, hardware probe, launching
app/skins.js       Skins: built-in looks, colors from cover art, generated skins, validation of .efskin files
app/quit.js        Quit to EchoForge: safe close, quit shortcut and the controller combo (app/padwatch.ps1)
app/pads.js        PS3 controller setup: spots a missing RPCS3 controller profile and writes one for the connected pad
app/app-updates.js EchoForge's own updates from GitHub Releases: check, verified download, start the installer
app/emu-updates.js Emulator updates from official GitHub releases: check, verified download, backup, roll back
app/guide.js       Guide content and the first-run tour steps
app/preload.js     Safe bridge to the UI
app/splash.html    Splash screen
app/index.html     Shell     app/styles.css  Design system     app/renderer.js  UI
app/data.js        Console + emulator catalog and per-PC tuning rules
app/assets/        logo.svg, icon.png, icon.ico
tools/             make_icon.py (icon from the logo), make_test_library.py (fake library for testing), build_shadps4.cmd / build_rpcs3.cmd (build from source), install_emulators.ps1 (Xenia Canary, xemu, DuckStation, Dolphin, PPSSPP from official releases)
test/              guide_test.js (Guide links and tour targets), emu_updates_test.js (emulator updates against a fake release feed): npm test
docs/RESEARCH.md   Emulator research, firmware table, build toolchains, roadmap
```

## Testing without touching your real profile
```powershell
$env:EF_PROFILE="$env:TEMP\efprofile"; npm start
```
`EF_SNAP=<dir>` saves screenshots of the splash and main window, then quits. It only works when running from source.

## Toolchain on this PC (for building cores)
Visual Studio 2022 (C++ + Clang), CMake, Ninja, LLVM, Vulkan SDK, 7-Zip, Git, Python, Node. Add LLVM and 7-Zip to your PATH:
```powershell
[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ';C:\Program Files\LLVM\bin;C:\Program Files\7-Zip', 'User')
```
Qt 6.8.2 (MSVC 2022, with Multimedia) is installed at `C:\Qt\6.8.2\msvc2022_64`. Pass it to CMake with `-DCMAKE_PREFIX_PATH=C:\Qt\6.8.2\msvc2022_64`, or set `QTDIR` to it for RPCS3. See docs/RESEARCH.md §4 for the full build recipe.

**shadPS4 from source:** run `tools\build_shadps4.cmd`. It clones or updates `%USERPROFILE%\src\shadPS4`, builds it, and installs `shadps4.exe` to `%LOCALAPPDATA%\Programs\shadPS4`. EchoForge's **Emulators → Auto-detect** then picks it up.

**RPCS3 from source:** run `tools\build_rpcs3.cmd` (needs Qt 6.12.0 at `C:\Qt\6.12.0\msvc2022_64`). The first build takes about 75 minutes because it builds LLVM; after that it's incremental. It installs to `%LOCALAPPDATA%\Programs\RPCS3` and never overwrites RPCS3's game data folders (dev_hdd0 etc.).
